# Using Nibbli as an AI agent

Nibbli is PixiBun's local atelier apprentice: Tester verifies existing behavior, while Artist accepts bounded drawing plans. Both use the same real UI [controller](../../scripts/nibbli/controller.ts), independent pixel/file observations and immutable attempt memory. Artist v0.1 is conversation assisted. Mock plans exercise the pipeline without a model or paid service. Neither mode establishes autonomous model creativity or training.

## Start a session

Use Node 22 and installed Playwright browsers. `npm run nibbli:artist -- --conversation` builds a frozen candidate and opens a disposable Chromium project. The runner prints an evidence directory and its `inbox`. Use `--project firefox` or `--project webkit` for a separate session. `npm run nibbli:artist -- --mock` exercises the complete pipeline and three-correction stopping rule in all three browsers, with zero retries.

The goal is a readable 32×32 ghost, two eyes, exactly three opaque colors and a transparent background. The goal contains no drawing coordinates. Choose the palette and coordinates yourself. The fixed first goal deliberately keeps frame/layer changes and animation outside Artist v0.1; those operations remain available in the separately qualified Tester controller.

Read each new `inbox/<round>-<phase>-<request-id>.request.json`. Write a sibling `<round>-<phase>-<request-id>.reply.json` containing exactly `{ "requestId": "the-request-id", "value": { ... } }`. Write to a temporary sibling first and rename it once complete, so a half-written response cannot be consumed. Do not reuse IDs or overwrite responses. Never place credentials in these files. Malformed responses stop the attempt and remain evidence; they are not silently retried.

For `phase: plan`, return the [ArtistPlan contract](../../scripts/nibbli/artist/protocol.ts): `protocol: 1`, the supplied `goalId`, a brief `rationale`, three distinct six-digit RGB strings in `palette`, and `commands`. Command shapes are:

| Operation | Fields | Boundary |
| --- | --- | --- |
| Select tool | `op: "tool"`, `tool: "pen"`, `"bucket"` or `"eraser"` | Choose explicitly before painting |
| Select color | `op: "color"`, `hex: "#rrggbb"` | Must belong to the original three colors |
| Draw gesture | `op: "stroke"`, `points: [{x, y}, ...]` | Integer coordinates 0–31; ≤128 points |

The controller explicitly selects the one-pixel brush and disables clean-corner filtering through the UI before Artist work. Use pen/eraser segments that are horizontal, vertical or exactly 45 degrees. A bucket gesture has exactly one point. Every batch must explicitly choose its tool and color before painting; eraser requires only its tool. Corrections retain the original palette. The entire batch, including independent tool semantics, is validated before the first UI edit. The model cannot request JavaScript, shell operations, state writes, arbitrary file paths, test edits or other controller capabilities.

For `phase: critique`, inspect the actual `round-<n>-screen.png` and `round-<n>-native.png` in the attempt directory. Requests include those PNGs as Base64, native RGBA and independent color/alpha counts. Do not treat screenshot colors as native pixel values: grid/underlay/display scaling can differ. Return `protocol`, `goalId`, `decision: "accept"` or `"correct"`, `planning: {meetsGoal, explanation}` and `artistic: {silhouette, eyes, palette, explanation}`. Each artistic score is an integer 1–5. Explain visible shortcomings and their relevance to the goal. A correction decision leads to a new plan request carrying the preceding observation and critique. At most three correction plans are allowed.

## Artist Hands — bounded editing of existing artwork

Use `npm run nibbli:hands -- --mock` for free deterministic editing coverage, or `npm run nibbli:hands -- --conversation` for a conversation-supplied repair plan. It uses a disposable two-frame, two-layer ghost fixture with misaligned eyes. This fixture tests editing, not original artistic planning. The conversation receives the creative repair goal without prescribed edit coordinates, the actual screenshot/composite and independently decoded project layers. The same provider-neutral inbox, request identity, zero-dollar default, eight-call limit and three-correction stopping rule apply. Future adapters implement [HandsAdapter](../../scripts/nibbli/artist/handsLoop.ts); no model/provider is selected automatically.

Hands has a separate envelope from the v0.1 drawing protocol: `{protocol: 1, observationId, edits: [...]}`. Every edit names `frameId`, `layerId`, `rect: {x, y, width, height}`, `reason`, `expectedChange` and `protectedLayerIds`. Translations have `op: "move-selection"` or `"copy-selection"` and `delta: {x, y}`. An in-place mirror has `op: "flip-selection"` and `axis: "horizontal"` or `"vertical"`, without a delta. Extra fields are refused. Use the supplied stable IDs. Explain the observed problem, why the chosen tool addresses it and the intended pixel result. Explicitly list every other layer, including layers in other frames, as protected. A critique has exactly `protocol`, `observationId`, `decision`, `planning: {meetsGoal, explanation}` and `artistic: {score, explanation}`; score is 1–5 and remains an opinion. Inspect the new actual observation before replying.

Hands supports only 32×32 projects and lossless integer translation/copying of a rectangle at least two pixels wide/high into empty space on the same frame/layer. Source/destination overlap is allowed for moves; copies require disjoint rectangles and preserve the entire source. Clipping, overwriting, partial alpha, hidden RGB in the selection, locked/hidden targets and generated/blended targets are refused. Select a rectangle containing actual target-layer artwork. Every batch is preflighted before selecting/moving/copying anything, binds one observation, contains at most four edits and preserves all other metadata/pixels. A fresh project download rejects stale workspace content before execution. The session admits at most twelve edits, ten minutes and the existing 160-action budget, with additional conservative overhead reserved for Copy/Paste. The actual gizmo must be visible, sufficiently enlarged, have a grip owned by its move body and match the specified rectangle/destination; playback and unfinished selections are refused. No script or direct application-state write is accepted.

`npm run nibbli:hands -- --conversation --copy` requests a conversation plan for a disposable ghost with one existing eye. The goal asks for a matching copied eye without specifying coordinates. Default Hands conversation mode selects the earlier alignment journey; each command opens one inbox rather than silently waiting for several unrelated plans. Mock mode without `--copy` includes the full Hands fixture set. Each plan also retains the 64-action limit: conservative reservations charge 12 actions per move or 16 per copy plus eight overhead actions. A four-copy batch exceeds that bound and is refused before UI execution despite meeting the four-edit schema limit. Native copy qualification must cover actual workspace Copy/Paste shortcuts, centered floating-paste geometry and placement at the validated destination; no OS clipboard or application-state injection is used. Test fixtures cover both an eye and an asymmetric multicolor motif with transparent holes at different zooms. Consult current status for terminal verdicts; implementation and discovery are not qualification.

`npm run nibbli:hands -- --conversation --flip` selects one asymmetric horizontal mirror journey. The chat chooses its plan from the actual observation; no provider is hardcoded. Mock mode without a journey flag retains all earlier cases and adds both axes, odd/even rectangles, 800%/1600% zoom, Cancel and rejection fixtures. Mirrors permute exact RGBA inside the selected rectangle, preserve every outside pixel and must change visible artwork; symmetric no-ops are refused. Partial alpha, hidden RGB and all existing layer, canvas and stale-plan boundaries remain. Each flip reserves twelve actions plus the same batch overhead. The real HUD button is used; a native screenshot and pixel observation of the uncommitted preview are retained. Cancellation is a trusted controller diagnostic and is not exposed as a planner command.

`npm run nibbli:hands -- --conversation --rotate` selects one quarter-turn editing journey. A rotation edit has exactly the common identity/rectangle/explanation/protection fields plus `op: "rotate-selection"`, `degrees: 90`, `180` or `270` clockwise and `pivot: {x, y}` in canvas coordinates. It has no delta/axis/algorithm field. Specify the pivot explicitly, including half-pixel centers for odd rectangles. The entire rotated rectangle must align to integer pixel boundaries and remain within the 32×32 canvas. All destination cells outside the source must be transparent zero RGBA. Quarter turns use an independent scalar pixel-center permutation; no product rotation engine or bounding helper generates the expectation. Empty/symmetric no-ops, partial alpha, hidden RGB, non-grid placement and all earlier safety violations are refused. Each rotation reserves sixteen actions plus the unchanged batch overhead; a four-rotation batch exceeds the existing 64-action cap.

The controller checks the real selected bounds and pivot reticle, moves that reticle with the mouse when necessary, selects RotSprite through the actual Tools panel, then uses the quarter-turn HUD controls. It checks the actual degree/bounds, retains the preview and verifies preview/commit agreement. Cancel is a trusted diagnostic option outside the planner schema. Mock fixtures cover centered/corner pivots, odd/even/mixed-parity rectangles, 800%/1600% zoom, all three quarter turns, previous Undo history, saved files and safe refusals. Free angles such as 37° remain outside the planner contract. R3 requires a separate bounded diagnostic and silhouette/palette assessment; it must not borrow the exact-quarter oracle or count an artistic opinion as pixel-exact qualification. Implementation alone is not a terminal browser verdict; consult current status.

After each move, copy, flip or quarter turn, independently decoded project metadata and every layer's RGBA must match the frozen expectation. Undo must restore the entire preceding project and Redo must restore the exact edit; then screenshot critique, saved reload and exported PNG/project checks follow. Failed checks stop with the original plan and evidence retained. Native OS pickers, cross-layer copies, larger project dimensions, free rotation/scaling and general M4 qualification remain separate work. The fixture deliberately disables the native save picker, as in Artist v0.1. Read the actual run `outcome.json`; adding a command does not establish a passing browser result or close M3 playback stability.

## Evidence and failure attribution

Read `outcome.json` first. A passing browser case is inconclusive if source or compiled build changed. Each attempt retains the goal, exact requests/responses, validated plans, action journal, screenshots, native pixels, critiques and decoded save/export evidence. Reports keep three assessments separate:

- Tool correctness is checked by independent pen/fill/eraser expectations and exact save/reload/project/PNG bytes.
- Planning compliance is an attributable agent opinion, alongside independent dimension/palette/alpha constraints.
- Artistic quality is an attributable agent opinion awaiting human review. Mock scores are explicitly not artistic evidence.

When a check fails, preserve it. Inspect whether the product, controller usage, adapter or independent expectation caused the mismatch before proposing a separate repair. An agent's critique cannot relax the expected pixels, modify tests, approve itself aesthetically or erase failed attempts. Reusing a candidate strategy needs review; experience storage does not train model weights.

## Provider adapters and budgets

The [ArtistAdapter interface](../../scripts/nibbli/artist/protocol.ts) provides `quote(request)` and `respond(request, signal)`. Every request carries `specification`: purpose/instructions and provider-neutral plan/critique JSON schemas. Runtime validation additionally enforces cross-field palette, tool and budget rules. A future OpenAI, Gemini, Claude or local adapter translates this contract; no provider or model ID is hardcoded. Its request includes the goal and observation, never product internals. Use a trusted adapter implementation, select credentials/model externally, bound its network deadline and return usage/provenance. Do not automatically select a paid provider or fall back to one after an error.

Defaults permit zero dollars, eight adapter calls, 160 total plan actions, 64 actions per plan, 2,048 total gesture points, 32 KiB replies, 600 KiB requests and 40,000 reported tokens. The session deadline is ten minutes; individual UI calls retain the controller's existing timeouts. A trusted metered adapter must quote conservative token/cost upper bounds before calling its provider. Unaffordable calls are refused before invocation; usage exceeding a reservation stops further work. These checks depend on honest adapter estimates/usage and are not a provider-side billing guarantee. Set a provider-side spending limit when adding a metered adapter.

The conversation adapter makes no network/model call and reports zero runner spend. The surrounding chat's token use is outside that runner; zero does not mean the chat service is free. Mock runs make no paid calls. Provider integration and a real model's artistic/planning capability remain unqualified until connected and independently evaluated.

Keep all run payloads local and ignored under the [archive policy](../archives.md). Commit or publish source/contracts only with the user's explicit approval. Preserve original evidence and source/build labels through publication.
