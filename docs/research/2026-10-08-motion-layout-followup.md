## Findings and changes

A native-worker diagnostic delayed motion results by 400 ms while the source cel lasted 125 ms. On the previously published application, the displayed raster did not change during Play Loop: the viewport effect invalidated each response as the elapsed-time controller requested another pose. Playback now waits for the current pose to finish presenting, retaining elapsed-time sampling and bounded worker ownership. Pausing/resuming does not lock the controller on an unchanged preview index. Renderer deadlines, cancellation, stale-source refusal and atomic bake publication remain intact.

Motion capture intentionally moves the active layer/selected detail. The supplied screenshot names a photometric layer, so a stationary base drawing under that moving layer is a plausible explanation; the exact user asset was not available as a project file. The explicit **Merge artwork & animate** action combines the current frame's visible color layers with native opacity/blending into one owned color layer, then captures all that artwork despite a prior area selection. It refuses locked/mismatched visible buffers, normal maps, floating selection, co-draw and an already open session. Hidden layers keep their ownership. Preparation is a separate structural Undo step, published through the real workspace transaction. Cancel then Undo restores the separate layers; after Bake, Undo first restores the unbaked combined artwork. Older rigs whose source was merged require a fresh capture. Active-layer capture keeps its existing meaning.

During motion, the onion canvas is cleared and hidden, preventing neighboring drawings under transparent preview pixels. Closing motion redraws ghosts. Bake already replaced the source cel with the sampled Start pose; it did not insert an extra original cel. Native translated-pixel checks now verify both first and final baked poses and exact Undo/Redo.

The preview counts painted samples that lie outside the document, ignoring transparent rotated bounding padding. It shows a crop warning for the current pose. The canvas still clips those samples. This warning does not prevent cropping, automatically enlarge the canvas, or measure detail changes caused by arbitrary-angle RotSprite resampling. Tiny-detail/contact quality remains a separate evaluation area.

Buttons now center their contents consistently, and hover/press feedback keeps their geometry in place. Motion history actions use equal columns, pose buttons have fixed heights, preview controls retain both columns, and primary motion/shadow actions share 36 px height and 12 px text. Numeric rows use consistent widths/type. The inspector reserves scrollbar space. The timeline row has a fixed height; onion help uses a reserved wide-desktop slot and a button description at compact widths, avoiding layout displacement and wrapping.

The left tool shelf restores the earlier 40 px overlapping-well cluster, 14 px corner actions/swatches and narrow ellipsis trigger. Swap, reset, primary/secondary swatches and the flyout retain their behavior. These requested small targets produce a known Axe target-size finding. The compiled accessibility test records every serious/critical finding, accepts only target-size nodes inside this exact dock, and still rejects other findings. This is an explicit usability tradeoff, not a WCAG conformance claim. The larger Palette/pinned picker remains available.

The canvas tools popup had a separate pointer-ownership defect: a real Chromium diagnostic could click Eraser but Pen stayed selected. Menu pointer events bubbled into the viewport, which captured the pointer before the tool button received its selection. The popup now lives in a portal and consumes its entire pointer sequence. Tool choice uses one click/context-menu action, avoiding duplicate color swaps. It shows ten labeled drawing, selection and shape tools using canonical icons/shortcuts. Shift+F10 and the Context Menu key open it from the focused canvas; arrows/Home/End, Tab containment, Enter and Escape support keyboard use. Actual measured dimensions keep it inside the window. It closes when the Studio viewport becomes hidden on a small screen, and restores the opener only when still visible.
