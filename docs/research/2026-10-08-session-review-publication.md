Source inspection found inconsistent sampling for saved fractional translations: static endpoints sent their raw translations to the renderer, while playback and bake used integer interpolation sampling. Static preview now uses the same endpoint interpolation; saved fractions, fractional pivots and existing rounding remain accepted. Position controls intentionally enter whole pixels. [ECMAScript's normative Math.round definition](https://tc39.es/ecma262/multipage/numbers-and-dates.html#sec-math.round) supplies the tie-toward-positive-infinity behavior; changing this to half-away-from-zero would alter negative half-pixel saves.

All six failed on input values before reaching a pixel comparison; they did not reproduce a renderer defect. The first full compiled attempt also hit those fixture failures and was deliberately stopped during Firefox. Those original results remain preserved. The corrected regression imports a valid v4 saved rig with fractional translations, verifies that the saved setting survives Open, then compares native preview/baked/Undo/Redo pixel hashes. Its verdict is recorded below; no unfixed-build pixel verdict is inferred from the original input failures.

The remaining-work review separates repaired defects from feature proposals and real-world qualification. No participant/device/assistive-technology study, generic derived-layer motion, multi-part skeleton, deployed two-build migration or compatible rollback is fabricated by this review.
