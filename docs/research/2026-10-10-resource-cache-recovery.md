## Recovery behavior

The service worker captures its original cache handle at event arrival. Optional opening, reads and writes settle after rejection, synchronous exception or a 250 ms deadline. Static resources start their healthy network fetch immediately; default resources keep cache-first behavior and try the network after unavailable storage. Default opening and reading have separate deadlines and can together take up to 500 ms. Deadlines settle responses/event lifetimes; they do not abort native storage operations. A cache response arriving after its deadline is unavailable to that fallback; physical-device cache latency remains unqualified.

Readable cached resources remain usable offline. A failed HTTP refresh also prefers a readable cached response. Unavailable cache plus failed network returns an explicit resource error, never substituted HTML. Worker bootstrap fragments retain the existing synthetic-response handling. Mandatory installation still requires a complete offline shell; activation and waiting-update ownership contracts remain intact. Warming uses the originally captured handle and does not reopen a retired bucket.
