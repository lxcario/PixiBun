### Limits and deliberate policies

The dispatcher uses one shared compute thread. Cancelling one request interrupts its pending peers with a retry error; it does not silently run them on the main thread. Small synchronous fallback still blocks until it returns, and the work-unit ceiling is an admission policy rather than a measured maximum latency. Larger fallback jobs require a worker. GIF initialization fallback retains the existing export geometry budget.

Registry bytes estimate live RGBA rasters; they are not total browser/GPU/process memory. Combined raster, history, temporary staging, export, and CRDT admission budgets remain Phase 3. No long-duration process-memory benchmark was performed.

Collaboration verification uses an independent replica and the real wire receiver with a simulated channel, rather than two live WebRTC browsers. Host-owned structure remains the existing collaboration policy. Local undo publishes a new LWW pixel write; selective undo of an artist's edits amid concurrent remote edits is not implemented. Shared clip/palette metadata and a broader command-service redesign remain outside this phase.

Browser checks use Chromium on the development server, and the available runtime remains Node 26.5.1 rather than declared Node 22. Production compilation passed. ### Research behind the contracts

- [W3C IndexedDB transaction scheduling](https://www.w3.org/TR/IndexedDB/#transaction-scheduling) serializes overlapping write transactions. The editor's version comparison belongs inside that transaction; transaction serialization alone cannot identify an obsolete editor snapshot.
- [W3C Service Workers](https://w3c.github.io/ServiceWorker/#service-worker-global-scope-skipwaiting) permits forced activation. Deferring it until windows close is an application policy to protect editing sessions and their loaded chunks.
- [Dexie's reading-hook documentation](https://dexie.org/docs/Table/Table.hook%28%27reading%27%29) supports reconstruction at the read boundary. Its [transaction guidance](https://dexie.org/docs/Tutorial/Best-Practices) motivates preparing binary data outside save transactions. Existing atomic recovery/duplicate commits use short `Dexie.waitFor` copies where necessary.
- The [WebKit Blob-storage issue](https://bugs.webkit.org/show_bug.cgi?id=188438) records similar historical failures and later reports. It supplies context for the reproduced error; it does not establish that every current Safari version has this defect.
- [Playwright issue 42775](https://github.com/microsoft/playwright/issues/42775) reports that WebKit offline emulation rejects even valid service-worker responses. The offline scenario therefore shuts down its own forwarding origin, retaining real production responses and real CacheStorage behavior. It does not skip WebKit or seed the cache manually.
- [Official Node 22 checksums](https://nodejs.org/dist/latest-v22.x/SHASUMS256.txt) were used to verify the workspace-local runtime. The downloaded Windows x64 archive's SHA-256 was `2b0ff57b049cda1bbcea2240eec20467018713c1efe1f7360c2681859b90ed71`.

No additional pixel-art feature research was needed for these browser/storage contracts. The original audit's academic, book, and studio sources remain the basis for the feature phases.

### Limits and deliberate policies

Save protection is optimistic concurrency, not a writer lease or automatic merge. Both tabs can draw; the obsolete writer preserves its work and must save a copy or export it. The active editor always supplies an expected saved version. The low-level storage helper retains an unchecked optional argument for existing internal/test CRUD callers; it is not a general multi-writer transaction API. Saved copies have independent identities. A conflicted workspace cannot silently discard itself while opening another project.

The 512 MiB limit is a conservative application admission policy, not a measured browser-process ceiling or a mobile-device guarantee. It estimates known retained CPU data and major staged operations. GPU allocations, browser/codec/IndexedDB internals, previews, floating selections, and some intermediate composition allocations remain outside the accounting. Collaboration estimates use a conservative per-entry approximation. Existing project/history limits still apply. Device memory profiling and long-duration stress runs remain follow-up verification.

Offline support requires a successful online visit and completed worker/cache preparation. First-ever offline installation and arbitrary unvisited lazy assets are not guaranteed. The shell-dependency limit is 128 entries plus 50 evictable dynamic entries; it is not a cache byte quota. A waiting update applies naturally after all tabs close. No artwork is reloaded automatically.

Windows Playwright WebKit is not certification on Apple Safari or iOS. Real pen hardware, mobile memory behavior, and a full hostile two-browser WebRTC session remain outside this verification. Node 22 checks use the existing installed dependencies; no clean reinstall or remote CI execution is claimed.

Cross-tab checks use two clients running this implementation. Older released clients do not perform the new save-version check, and their raster readers may expect physical Blob records. A deployment/rollback must retire those clients before mixing writers and validate the storage transition; compatibility with simultaneously running old application code is not claimed. Existing stored Blob records remain readable by the new implementation.

## Phase 4 — Animation stability review and protected regions

Status: **Implemented locally; full repository gate, all 113 editor checks, and all 18 production checks passed under Node 22.** Changes remain uncommitted and undeployed. Artist usefulness evaluation remains outstanding. TestSprite was skipped by explicit user instruction.

### Artist workflow

Open **PixiTools → Review animation**. Choose an existing clip, or create a clip from all frames. Scan to compare consecutive poses; optionally compare the last pose with the first for a loop. Use the existing timeline Play control to watch the selected clip.

The report provides a before image, aligned next pose, and color-coded changed pixels at 1×, 4×, or 8×. It reports outline/silhouette changes, visible color/alpha changes, palette RGB additions/removals, eight-connected cluster counts, and A→B→A pixel reversals when a following pose exists. Integer whole-sprite translation can be compensated within ±3 pixels on each axis. These numbers are review cues, not a universal aesthetic score or proof of a defect.

Select a rectangle on the canvas, then open **Regions and protection** and save its name and purpose:

- **Protect during Pixel Cleanup** retains those pixels exactly in the existing Scan Artwork / Apply Cleanup workflow. Protection applies inside the selected clip, including its matching-layer cleanup across frames.
- **Ignore intentional motion** excludes the region from silhouette, color, palette, and reversal comparisons.
- **Watch contact drift** reports movement of the alpha-weighted center in that fixed canvas region. Missing content is reported explicitly.

Regions use the selection's rectangular bounding box, including when the original selection is a lasso. Coordinates stay fixed on the canvas. Drawing, other filters, and transforms remain editable; this is not a global layer lock or a motion-tracking constraint.

**Mark this change intentional** saves a clip annotation for the exact interval content and settings, including the following pose when it supplies a reversal cue. Annotations can be reopened or cleared. Pixel, timing, region, or relevant comparison-setting changes require review again. An unrelated pose does not expire an unchanged interval judgment. Frame identities prevent an old mark from silently moving onto a different pair after frame deletion/reordering. Both regions and marks survive local save/reload and portable project admission/hydration, and participate in existing undo/redo.

### Scope and limits

Scans accept 2–64 frames, dimensions up to 256 × 256, and at most one million aggregate frame pixels. These are admission limits, not measured performance guarantees. Larger projects can use shorter clips or smaller canvases; source artwork is not automatically resized. The browser-less fallback admits only 8,192 aggregate frame pixels. The worker path is cancellable; cryptographic hashing of a single bounded frame completes before the next cancellation check.

Alignment handles only small whole-sprite translations. Rotation, deformation, moving subparts, opaque backgrounds and ambiguous repeated shapes can produce misleading comparisons. It does not estimate optical flow. Cluster counts can indicate a topology change but do not identify the correspondence of individual clusters; ignored regions also change the analyzed mask. Contact-center drift does not establish a foot's world-space position or gameplay collision behavior. An empty contact region is not automatically a defect. The display shows canvas pixels; some aligned edge changes counted by the analysis lie outside the display.

Protection is limited to the analyzed Pixel Cleanup operation in the selected clip and uses fixed coordinates. Resizing or shifting artwork may require new region definitions. It does not constrain automatic morphing, rotation, palette grading, or direct painting. There is no automatic repair or selective remote undo. Review annotations are local project metadata and are not synchronized through the current co-draw wire protocol. Older application versions may drop optional review fields when resaving a project; deployment compatibility limits from Phase 3 still apply.

Technical verification does not establish that artists find these cues useful. The next product acceptance step is a small artist study on original/licensed animations, recording useful versus intentional alerts and time to locate an artifact. No artist-rated success, automatic aesthetic improvement, mobile-device certification, or TestSprite verdict is claimed.

Original per-pose holds follow their frames: GIF rounds to 10ms units with a 20ms minimum, APNG has a 10ms minimum, and videos depend on native recording/encoding schedules. Godot preserves source milliseconds. Scoped sheets remap original frame positions and include only complete clips. Duplicate labels receive deterministic suffixes; quoted Unicode names survive actual engine import. Playback speed previews remain separate from exported source holds.
- Sprite-sheet resources reference the PNG actually downloaded. Failed compositing refuses export instead of substituting blank frames. TexturePacker metadata includes frame durations and clip sequences; Unity/Phaser JSON remains unverified metadata.
- **Export → Godot Kit** downloads one offline ZIP: native-size diffuse atlas, SpriteFrames resource, manifest with clip sequences and anchors, texture import settings, project, comparison scene and instructions. Optional normal maps use the same atlas regions and nearest filtering. The scene compares original color with runtime output, offers named clips, and provides palette/light toggles.
- **Palette → Roles and index bindings** adds stable entry IDs and bounded role names. A selected rectangle explicitly assigns matching RGB pixels to a register on the current frame; later matching bindings win. Unresolved duplicate colors and non-palette pixels refuse indexed export. All 256 register values remain usable because raw index bytes and source alpha live in separate opaque data textures. The kit includes LUT, shader, palette roles/bindings, tracks and speed metadata. Painting remains RGBA; this is explicit export identity, not a native indexed-painting mode.
- Palette roles, bindings, added palettes/ramps and cycle track edits use Undo/Redo. Existing IDs survive appended ramps, and project save/import preserves canonical metadata. Portable/async palette snapshots deep-copy nested metadata. Roles admit at most 256 entries, 64-character labels and 128 bindings; admission rejects duplicate/dangling register IDs and invalid rectangles. History admission includes palette snapshot bytes and the growth of role/binding metadata.
- Kit admission reserves estimated combined memory before allocating atlases; limits are 8192px per atlas dimension and four million atlas pixels, including padding. Export is cancellable, refuses stale artwork/metadata, checks after asynchronous boundaries, times out stalled native PNG encoding, ignores late cancelled callbacks, and releases owned leases on failure. ZIP paths are flat and bounded, with standard CRC32 and SHA-256 asset hashes. Native encoders/GPU allocations are outside the application-owned estimate.

### Research and engine findings

Godot defines absolute duration as relative duration divided by animation FPS and playing speed. The exporter uses relative milliseconds at speed 1000. Ping-pong is represented as a flattened period with each endpoint once; this keeps the same sequence in the editor, manifest and engine. [Godot 4.7 SpriteFrames reference](https://docs.godotengine.org/en/4.7/classes/class_spriteframes.html).

The first real engine run found that using a resource dictionary field named `loop_mode` did not load its animations. Godot 4.7.2 serializes the loop enum under **`loop`**; the generated resource now uses that integer field. This was confirmed in the engine source and rerun locally. [Godot 4.7.2 SpriteFrames serialization source](https://github.com/godotengine/godot/blob/4.7.2-stable/scene/resources/sprite_frames.cpp).

The next rendered comparison found lost frame coordinates when CanvasTexture wrapped an AtlasTexture. The corrected sample wraps the paired full-atlas CanvasTexture inside an AtlasTexture, preserving the draw call's atlas UVs for diffuse, normal, index and alpha sampling. Actual rendering checks the frame regions and both X/Y normal directions. Godot documents CanvasTexture as a 2D diffuse/normal pairing with independent filtering, and expects X+ Y+ Z+ normals. [CanvasTexture reference](https://docs.godotengine.org/en/4.7/classes/class_canvastexture.html).

Textures use lossless import, no mipmaps, no premultiplication and no alpha-border modification. These settings keep the raw index/alpha data distinct and preserve original color edges. [Godot image import guidance](https://docs.godotengine.org/en/4.7/tutorials/assets_pipeline/importing_images.html). The kit drives an explicit elapsed-time uniform instead of relying on the shader `TIME` built-in's rollover and pause behavior. The older standalone normalized-index Godot shader shares the corrected cycle math, but retains its separate input contract and `TIME` clock. [CanvasItem shader reference](https://docs.godotengine.org/en/4.7/tutorials/shaders/shader_reference/canvas_item_shader.html).

Ferrari's palette-animation work motivates delivering the palette and runnable example together. That is a product inference, not evidence that the new roles workflow improves an artist's productivity. [Ferrari's GDC presentation](https://www.gdcvault.com/play/1023586/8-Bit-8-Bitish-Graphics). The academic, book and studio research in the original audit remains context; no new artist evaluation or licensed studio artwork was substituted for the original fixtures.

Play-once GIF output omits the Netscape looping extension; putting zero in that extension requests infinite looping. APNG instead uses `acTL.num_plays = 1` for one play. These format-specific representations preserve the same editor intent. [WebKit decoder investigation](https://bugs.webkit.org/show_bug.cgi?id=39857), [W3C PNG Third Edition animation control](https://www.w3.org/TR/png-3/#acTL-chunk).

### Scope and reproducibility

Entry IDs are scoped to their owning palette; maximum-length admitted palette names/IDs and missing frame identity have explicit boundary regressions. The shader uses GPU float: high rates or long elapsed times can lose phase precision. The measured one-byte BlendShift bound describes the tested fixture samples, not every possible track/time. Actual runtime hold observations and their 40ms scheduling tolerance are recorded in the engine reports; they are not a frame-rate or real-time performance guarantee.

This adapter targets Godot **4.7.2 on Windows Compatibility rendering**. Other Godot versions/renderers, mobile devices, Apple Safari/iOS, Unity, Phaser and long-duration memory behavior are unverified. Existing normal maps are exported as stored; no automatic convention inference/conversion or gameplay collision behavior is claimed. Native canvas compositing can alter RGB at low alpha: exact indexed admission uses the actual composed pixels and may require a matching extracted palette. Palette roles/bindings are local project metadata, not co-draw-synchronized data. Older versions can drop optional fields when resaving. Drawing/duplicating/resizing artwork may require updated selection bindings; orphaned bindings can be removed in the panel. ### Hardening

- Geometry is bounded to 256 pixels per axis, 16 poses and 262,144 total source pixels. Scene atlases must divide evenly. Palette lists, names, rectangles, materials, pins, seeds, hashes and all numeric ranges are validated before work.
- A conservative memory reservation precedes source reads and stays alive while comparison rasters are retained. Publication separately admits staging, workspace layer capacity and undo/redo metadata. Refused operations leave source artwork unchanged.
- An owned worker has a 30-second deadline, cancellation and a single-job slot. Transfers use owned copies so source comparisons remain available. Invalid raster sizes, pass shapes, tile indices, non-finite repetition diagnostics and malformed messages are refused. Large jobs cannot silently switch to main-thread execution after a worker failure.
- Snapshot checks cover project identity, frame/layer membership, pixel generation/revision, clip bounds and layer settings. Results cannot apply after edits or source changes. Disposal releases the retained reservation on cancellation, stale work, failures, replacement, application and unmount.
