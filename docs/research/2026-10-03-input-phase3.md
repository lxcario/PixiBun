## Problem and resulting behavior

Three new regressions first reproduced Undo acting behind an open dialog, a tool switch while typing in a nested editable element, and the Turkish `ı`/physical-I shortcut failure. A shared workspace input boundary now leaves events to open native/ARIA modal dialogs, editable ancestors, native fields and custom typing/slider controls. It also respects already-handled events, composition input, dead/process keys and AltGraph. Studio keyboard, image paste, both selection handlers, the lighting gizmo and desktop practice use that boundary. Modal-owned controls continue to work; the shared dialog wrapper does not indiscriminately stop every keyboard event.

Letter commands now use physical QWERTY positions, with the produced key as a fallback when no physical letter code is available. This includes letter-based tool, save/history and selection clipboard commands. Punctuation, numbers and navigation retain their key meanings. Help states the policy; this is not Turkish localization or a change to the OS layout. `KeyboardEvent.code` describes physical positions and can disagree with printed letters on other layouts. [MDN keyboard code](https://developer.mozilla.org/en-US/docs/Web/API/KeyboardEvent/code).

Unsupported Ctrl/Cmd/Alt combinations no longer fall through to bare tool or display-lens shortcuts. Native control Space/Enter/navigation retains ownership. Shift+H/V remains symmetry even with a selection. Previously both selection hooks could claim arrows and Escape: CenterViewport now delegates those transforms to one owner, avoiding a double nudge or commit followed by cancellation. Shared input guards also prevent the lighting gizmo's capture listener from acting behind a dialog. An explicit owner scope preserves the lighting handle's own slider keyboard controls while other workspace handlers yield to that slider.

The artwork viewport now declares `touch-action: none`; primary-touch drawing ignores secondary fingers through down/move/up/cancel. The rest of the interface keeps its existing browser gesture policy. No two-finger canvas navigation, pressure brush or phone Studio is introduced. Studio's existing 1024px minimum remains. The CSS policy tells the browser who owns gestures before dispatch; Pointer Events can otherwise receive cancellation when the browser takes over scrolling/pinching. [MDN touch-action](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/touch-action). Composition events are separately identified through the keyboard event's composition state. [MDN composition state](https://developer.mozilla.org/en-US/docs/Web/API/KeyboardEvent/isComposing).
