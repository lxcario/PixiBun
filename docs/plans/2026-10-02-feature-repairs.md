# Feature repairs, one phase at a time

Started 2 October 2026 following the illustrated handbook review. This is an implementation plan, not a release sign-off. Existing dated evidence stays unchanged. Completion requires executed checks and an updated guide; a screenshot alone is not a verdict.

| Phase | Work | Acceptance | Status |
| --- | --- | --- | --- |
| 1: Safer practice actions | Put Trace and Clear in ordinary pixel history; refuse edits without history or on locked layers; mount only the appropriate mobile/desktop Playground | Exact pixels return through Undo/Redo; rejected actions leave pixels/history unchanged; mobile never starts desktop lessons | Complete locally; [checks](../research/2026-10-02-feature-repairs-phase1.md) |
| 2: Separate practice from artwork | Preserve original project, buffers, timing, file association and undo/redo; explicit adoption under a new project identity; safe exit/reload/failure | Existing artwork survives entry, lesson switches and exit; refresh restores saved original; adopting practice cannot overwrite the original | Complete locally; [checks and qualified browser follow-up](../research/2026-10-02-feature-repairs-phase2.md) |
| 3: Drawing and preview controls | Wire Iso FREE for both preview and committed strokes; remove duplicate floating preview | Non-2:1 slopes match preview and committed pixels; one preview opens/closes | Complete locally; [checks and remaining qualification](../research/2026-10-02-feature-repairs-phase3.md) |
| 4: Export completeness and honest wording | Admit valid manual normals; label welcome text downloads accurately; qualify SVG approximation; export a matching unique-tile PNG and map with stale-result handling | Real output files and fixtures agree with labels, guide and importer expectations | Complete locally; [checks and importer qualification limits](../research/2026-10-02-feature-repairs-phase4.md) |
| 5: Final reconciliation | Refresh affected screenshots and guides; reconcile known-limit/public-copy claims; repair discovered reduced-motion startup; execute broader checks | No future feature represented as shipped; visible reduced-motion panels without hydration errors; new evidence describes its runtime and scope | Complete locally; [checks and qualification limits](../research/2026-10-02-feature-repairs-phase5.md) |
| 6: Recovery safety follow-up | Count the current source before archive payload loading; remove physical MIME fields from logical ArrayBuffer reads; show backup failure inside the dialog | Overflow refuses before payload reads; admitted archive bytes survive; both storage representations support separate-copy recovery; visible failure feedback and named checks | Complete locally; [checks, fixture budgets and limits](../research/2026-10-02-feature-repairs-phase6.md) |
| 7: Full regression and release readiness | Freeze the latest checkout; execute full browser suites; check dependency advisories, public deployment observations and update/rollback compatibility | Dated commands, source/build identity, retained failures and an explicit release decision with unresolved host/device boundaries | Complete locally; production approval remains pending; [execution record](../research/2026-10-02-feature-repairs-phase7.md) |

Local verification follows the recorded [local-only testing preference](../research/testsprite-plan-registry.md). No external upload or tunnel is authorized by this plan. Human studies, physical-device qualification, cloud backup and a native/mobile full Studio remain separate work; these repairs do not claim those capabilities.

The responsive mount uses React's [external-store subscription](https://react.dev/reference/react/useSyncExternalStore) contract with a matching server/hydration snapshot. Lifecycle checks must also account for the extra development setup/cleanup described in [Strict Mode](https://react.dev/reference/react/StrictMode).
