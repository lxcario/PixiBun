## 1. Zero-Cloud & Local-First Philosophy
PixiBun is architected as an offline-first, client-side application:
- All canvas manipulation, photometric lighting calculations, and animation exports run on the client device.
- Artwork and project data persist on-device in browser IndexedDB storage. The `window.__pixibunDb` and `window.__studioStore` debug handles are exposed only in development and test builds, including when those builds run on localhost. Production builds do not expose them on any hostname. Browser E2E tests use a development server to access these handles.
- No user account is needed. Local diagnostics default on; they can include error text and paths. Sending diagnostics requires opt-in, as described below.
- WebRTC P2P co-draw defaults to a local-network configuration without public STUN servers (`LAN_ICE_SERVERS = []`); public STUN requires `lanOnly: false`.

## 2. Secrets & Secret Hygiene
- PixiBun requires zero API keys or external authentication tokens for local or production use.
- **Never commit Personal Access Tokens (PATs) or API keys** to this repository. All environment keys should be configured via environment variables or secret managers (e.g. Vercel Project Settings) and never hardcoded in scripts or configuration files.
- If a token is ever accidentally exposed in development, immediately revoke and rotate it at [github.com/settings/tokens](https://github.com/settings/tokens).

## 3. Diagnostics Relay Security Boundaries & Threat Model
The optional crash and diagnostic relay endpoint (`/api/diagnostics/relay`) acts as a server-side proxy to an operator-configured upstream (`DIAGNOSTICS_RELAY_URL`). Its threat model and defense boundaries include:
- **Diagnostic Content Privacy:** Local diagnostic capture is enabled by default and records the page pathname (`window.location.pathname`) unless the caller supplies a route. Detail text is capped at 2,048 characters with a truncation marker. Error messages and stack traces are free text and can contain names, file paths, URLs, or browser environment data. Truncation is not redaction. Review diagnostic reports before opting into transmission; a zero-PII guarantee is not established.
- **Origin admission:** An Origin header is required and must match the request URL’s exact scheme, host and port; browsers send it with every POST, so a request without one is refused (403). The body must be sent as `application/json` (415 otherwise). These checks run before the rate limit, so refused requests spend no quota. This is browser-origin checking, not authentication or server proof of client consent: a non-browser client can forge both headers. Forwarded proxy headers do not replace that comparison.
- **Trusted Reverse Proxy Assumptions & Client IP Identity:** Client identity is `X-Real-IP`, else the last `X-Forwarded-For` entry (the one a single trusted proxy appends; the first entry is client-supplied). Security assumption: In production (e.g. Vercel, Cloudflare, AWS ALB), an operator-trusted edge reverse proxy must sanitize or prepend the client IP. In raw, direct Internet-facing Node.js deployments without an edge proxy, an adversary could spoof `X-Forwarded-For` headers to circumvent per-IP rate limits or exhaust quotas of other IP addresses.
- **In-Memory Token Bucket Limits & Multi-Instance Serverless Scaling:** Rate limiting (`capacity: 12, refillPerMinute: 12`) is stored in process memory via `TokenBucketStore`. This rate limit is local to the active Node.js / serverless worker container. In horizontally scaled or multi-instance serverless deployments, each container enforces its own rate limit independently; aggregate cluster throughput scales to (N_instances * 12 req/min) rather than an authoritative global ceiling. Enforcing a global cluster limit would require an external distributed cache (e.g. Redis or Upstash).
- **Payload Streaming Ceilings & DoS Mitigation:** Request bodies are streamed via chunk reader enforcing a strict 64 KB (`MAX_BODY_BYTES`) ceiling before buffering, bounding accepted request-body buffering (CWE-400 / CWE-770). Batches exceeding 100 events or containing invalid event fields are rejected before forwarding. Messages are bounded to 1,024 characters, routes to 512, detail to 2,062 including a truncation marker, and IDs/version strings to 128. Unknown event properties are omitted from forwarding. The reported client version is preserved separately from the server version.
- **SSRF Defense & Transport Security:** The endpoint ignores client-supplied destination URLs and forwards to the server-side environment variable `DIAGNOSTICS_RELAY_URL`, requiring HTTPS. Upstream requests enforce a 5-second timeout (`AbortSignal.timeout(5000)`) and reject redirects (`redirect: 'error'`). Server-owned HTTPS configuration is not a general SSRF certification; operators must review destinations, redirects and proxy trust.
- **Opt-In Transmission:** Diagnostic transmission requires explicit user opt-in; once enabled, captured error events can be sent automatically. Local client-side diagnostic capture in IndexedDB is enabled by default.

Local capture deduplicates matching kind/message/detail/route for ten seconds and admits a burst of 20 events with 60/minute refill per tab. At most 20 storage writes can be pending; serialized pruning retains the 200-entry ring. Excess events are dropped, not delayed indefinitely. Opted-in relay batches contain at most ten events and send after five seconds; overflow beyond that batch is not relayed. Consent is checked after storage and again at send time, and revocation clears pending batches. These are per-tab policies, not cluster rate limits or a durable delivery promise. Rejection serialization bounds traversal and handles circular values, BigInt and throwing accessors.

## Current generated-effect safeguards — 2026-10-01

Live lighting and glint layers use `source-atop` (On artwork only), keeping source coverage intact. The native project schema and Co-Draw structure allowlist accept this blend mode. Pixel history retains the mode and restores it on Undo/Redo, including replay baselines. Locked effects refuse editing; cancelled previews restore earlier pixels, metadata, blending and layer focus. These targeted safeguards do not establish general collaboration convergence or certify every graphics path. ## 4. Defense-in-Depth & Quality Gate Invariants
PixiBun enforces an automated local Quality Gate (`npm run gate`) wired into a local `.git/hooks/pre-push` gatekeeper. The configured hook runs documentation checks, typecheck, lint and unit tests. Hooks can be bypassed and passing checks are not a security certification. Relevant safeguards include:
- **CWE-409 Decompression Bomb Defense:** Image imports probe binary headers via `ImageHeaderProbe` (`imageHeaderProbe.ts`), rejecting dimensions $>8192\text{px}$ or pixel counts $>67\text{ MP}$ before memory allocation.
- **Workspace Envelope & Complexity Defense:** Runtime workspace mutations (canvas resize, layer additions, frame duplications) are pre-evaluated by `WorkspaceEnvelopeGuard` (`workspaceEnvelopeGuard.ts`) against the 64 Mpx / 2,000 layer ceiling before buffer allocation, reducing admitted raster allocation risk; browser, codec and other unregistered memory remain outside the estimate.
- **CWE-1321 Prototype Pollution & JSON Allocation Bomb Defense:** Project deserialization uses `SafeJson.parse` (`safeJson.ts`), stripping `__proto__`, `constructor`, and `prototype` keys, enforcing a maximum payload size of 50 MiB (`50 * 1024 * 1024` bytes), and limiting recursion depth to 32. Emits typed error classes (`SafeJsonPayloadLimitError`, `SafeJsonNestingDepthError`, `SafeJsonTraversalLimitError`, `SafeJsonOptionError`, `SafeJsonSyntaxError`). During recovery inspection, metadata traversal is bounded by a 50,000-node ceiling (`RECOVERY_INSPECTION_CEILINGS.MAX_METADATA_NODES`).
- **IEEE 754 Floating-Point Invariants:** Viewport transformations enforce `clampZoom` and `safeDivide` (`mathInvariants.ts`), preventing `NaN` propagation, zero-division, and negative coordinate corruption.
- **Safe Canvas Boundaries:** Selection extraction uses `SafeCanvas` (`safeCanvas.ts`) to bound allocation sizes and pad out-of-bounds reads. Other canvas readback paths use separate input checks and are outside this wrapper's scope.
- **WebRTC Packet Flood Mitigation:** Reliable co-draw traffic uses a 32 MiB retry queue and a 256 KiB packet ceiling. A transient disconnection pauses retry work and retains queued artwork for up to 30 seconds; recovery resumes the same deliveries. A delivery lacking acknowledgment for 30 seconds of active delivery time ends the session. Failed/closed transport and reliable-channel failure release queued bytes and timers. Invalid artwork terminates the session with an error and receives no acknowledgment; valid duplicate delivery IDs are acknowledged without applying artwork twice. Valid older packets without delivery IDs remain accepted. Presence traffic uses a single token bucket and may be dropped. These deadlines are application policies, not WebRTC standards or RFC 2212/RFC 2697 conformance claims.
- **Portable Co-Draw Metadata and Ordering:** Shared layer names use the same 128-character limit as project-file admission. Pixel timestamps and HLC tuple values must be safe integers; counters are nonnegative. Exhausting a safe counter carries the clock into the next millisecond before further increments, preserving ordering without unsafe arithmetic. Future remote clock drift remains bounded at admission. This protects protocol admission, not authentication of the peer or measured long-session performance.
- **Storage Resilience & Multi-Table Atomic Rollback:** IndexedDB operations detect `QuotaExceededError` and prune volatile telemetry caches (`storageResilience.ts`). Destructive project operations (`deleteProject`) run in single-transaction Dexie `readwrite` blocks across `projects`, `layerBlobs`, and `recoveryRecords`, ensuring full rollback consistency upon failure.
- **Streaming Archive & Forensic Recovery Defense:** Zero-dependency ZIP32 writer (`zipWriter.ts`) rejects path traversal (`..`), leading slashes, drive letters, backslashes, NUL bytes, and lone UTF-16 surrogates; caps payload writes at 64 KiB; snapshots preflight entry sources and binds `sink.write` exactly once to prevent prototype/getter mutation. Stored-project assessment (`assessStoredProject` in `recoveryDiagnosis.ts`) operates read-only via `[projectId+id]` keyset pagination and slices 24-byte headers with `ImageHeaderProbe` without decoding raster images or allocating canvas bitmaps. Untouched archive assembly (`recoveryBackup.ts`) guarantees read-only IndexedDB snapshot isolation with zero mutations; enforces a sealed non-forgeable trust boundary via module-private `WeakSet`/`WeakMap` structures; exposes strictly scalar metadata descriptors without leaking internal Blob handles, byte buffers, or stream factories; defends against multi-pass manifest mutation via fresh byte slices; and guarantees safe export streaming (`recoveryBackupTransport.ts`) with immediate abort capture on file handles and preflight 250 MiB memory ceilings with defensive chunk copying on in-memory fallback.

Untouched archive preparation also refuses more than 10,000 matching raster records before loading their payloads, within the same read-only transaction. The native count may scan the index range; this does not bound total browser memory. ArrayBuffer reads reconstruct a logical Blob and remove its physical MIME field, while other unknown fields still reach strict recovery validation. [Storage and archive limits](storage.md), [phase 6 checks (local archive)](../archives.md#record-docs-research-2026-10-02-feature-repairs-phase6-md).

Manual co-draw signaling admits version 1, a non-empty peer ID of at most 128 characters, offer/answer SDP of at most 262,144 characters and at most 256 typed ICE candidates. Candidate strings are bounded to 4,096 characters; optional mid, line-index and username fields are type/range checked before WebRTC construction. Parsing keeps the existing 1 MiB encoded-token ceiling and adds a 4,096-node traversal ceiling. An invite must carry an offer and a guest reply an answer. These are application workload policies; WebRTC does not define a universal 256-candidate limit.

Co-draw code copying awaits the Clipboard API's write promise. Denied or unavailable clipboard access selects the read-only code and offers manual copying. Success belongs to the visible code; tab changes, connection changes, closing and unmounting invalidate pending responses and clean up feedback timers. Clipboard permission does not establish peer identity or authenticate the invite.
