## Scope and evidence

This audit compares the supplied *Making PixiBun a World-Class Pixel Art & Animation Studio* report with the current checkout. The report explicitly had no codebase or user-session access; its competitor patterns and academic findings are design inputs, not observations about PixiBun. Code locations below were inspected in this checkout. The in-app browser loaded `/studio` but showed the `MobileStudioGate` at its narrow viewport; desktop interaction was checked with Chromium browser tests and 1024px/1280px screenshots. Existing uncommitted edits in `AtelierRail.tsx`, `StudioLayout.tsx`, `PixiBudAssistanceSection.tsx`, `ImportModal.tsx`, and four TestSprite plans predate this audit and are preserved.

PixiBun is a local-first pixel art and frame-animation editor. The main flow is landing page → `/studio` (`src/app/studio/page.tsx`) → `StudioLayout` → top `AtelierRail`, left `LeftToolbar`, `CenterViewport`, right `RightInspector`, bottom `BottomTimeline` and `StatusBar`. Drawing state is in Zustand slices (`src/stores/slices`); pixel buffers live in `src/lib/engine/bufferRegistry.ts`; compositing and onion ghosts are separate (`src/lib/render/compositor.ts`, `onionSkin.ts`). The existing `/playground` and onboarding overlay are optional learning surfaces. No user interviews, analytics, or performance measurements were available for this audit.

## Consequential verified findings

1. **P0, save trust:** A successful IndexedDB write is rendered as generic `Saved` (`AtelierRail.tsx`) and as `All changes saved` for screen readers (`StudioLayout.tsx`). Those strings can reasonably be mistaken for a portable copy; the report's browser-storage caveat applies. The underlying successful-write and revision checks are already present and must remain intact.
2. **P0, backup failure:** `ExportModal.tsx:645–658` invokes `DesktopFileSystem.saveProject()` and unconditionally closes. `desktopFileSystem.ts` returns `{success:false}` for cancellation or permission denial, while errors may throw. Serialization failures only log. The current UI gives no inline result.
3. **P0, silent onion state:** `BottomTimeline.tsx` allows enabling onion with one frame or while playing, while `onionSkin.ts:16` intentionally yields no ghosts. Explain the state without changing animation data.
4. **P1, workflow discovery:** A populated PixiTools panel and timeline already exist. The research's strong opportunity claim is plausible but unverified as user friction; an outcome-based task study should decide taxonomy changes.
5. **P1, viewport constraint:** `MobileStudioGate.tsx` withholds the editor below the `lg` breakpoint. This is a deliberate current limitation; a responsive editor would need panel and touch interaction design, not a small CSS patch.
6. **P1, brush preset targets:** Automated WCAG 2.2 scans in the browser found 20×16px quick size buttons below the 24px target minimum. The controls were enlarged to 24×24px, and focused axe scans across four themes now pass.

## Implemented verification observations

- At 1024px and 1280px desktop widths, the revised two-row top rail kept Save, Back up, Import and Export visible without horizontal clipping in screenshots and browser bounds checks.
- Browser tests exercised successful `.pixibun` writes, cancelled picker, local save wording and the one-frame onion explanation. The existing persistence, recovery, drawing and theme accessibility paths were also rerun.
- Toolbar preview controls expose stable `data-testid` values and accessible labels. Older tests that expected native `title` attributes were updated. The later preview revision replaced the shared heart animation with distinct scenes and increased text sizes; 43 scenes passed focused unit checks, and Lasso and Wand results were inspected in Chromium.

## Specific unverified concerns

Color-picker placement, right-panel transition symmetry, delayed close, button scaling, inspector jumping, tool findability, and onboarding effectiveness require desktop runtime observation or user testing. The report cannot prove these defects. Project safety changes need isolated tests with failed/cancelled writes and existing artwork; do not change file format, undo semantics, or storage migrations as part of this UX slice.
